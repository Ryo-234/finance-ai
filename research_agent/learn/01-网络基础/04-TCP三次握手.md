# TCP 三次握手 - "打电话确认"

> ⏱ 阅读时间：1 分钟

## 是什么

浏览器和服务器**建立连接**前的三次确认。**所有 HTTP 请求前都要先握手**。

## 类比：打电话

```
你：喂，听到吗？           (SYN)
他：听到了，你能听到我吗？ (SYN-ACK)
你：能听到，开始说正事。   (ACK)
```

## 为什么需要 3 次

**防止"网络延迟导致误连接"**。

例子：
- 你发了一次"连接请求"，但网络延迟 1 分钟
- 1 分钟后服务器收到，发回确认
- 这时候你**已经放弃**了，但服务器不知道 → 浪费资源

3 次握手确保**双方都准备好了**才传数据。

## 过程

```
客户端                   服务器
  | --- SYN --->            |    1. "我要连你"
  | <--- SYN-ACK ---        |    2. "好，我也准备好了"
  | --- ACK --->            |    3. "OK，开始吧"
  | === 数据传输 ===         |
  | === 数据传输 ===         |
  | <FIN-ACK>... 关闭       |    4. 最后 4 次挥手关闭
```

## 关键点

- **HTTPS 比 HTTP 多一步 TLS 握手**（建立加密），所以**更慢**
- 一个 HTTP 请求要"握 1 次手 + 发 1 次请求 + 握 1 次手断开" → **比 UDP 慢**
- HTTP/2 和 HTTP/3 改进了：一次握手多次请求（**多路复用**）

## 跟你的项目关系

- **正常不用关心**，浏览器自动处理
- 但**性能调优**时会涉及：减少握手次数（用 Keep-Alive 长连接）
- 理解这个能看懂为什么"**长连接比短连接快**"

## 常见坑

- **SYN 攻击**：黑客发一堆 SYN 不回 ACK，服务器资源耗尽
  - 防御：SYN Cookie、防火墙
- **TCP 粘包**：连续发数据可能粘在一起
  - 解决：加分隔符、消息长度
