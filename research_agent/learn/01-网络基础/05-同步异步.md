# 同步 vs 异步 - "排队 vs 扫码点单"

> ⏱ 阅读时间：1 分钟

## 是什么

**同步**：你排队买奶茶，**必须等前一个人买完**你才能买。
**异步**：你扫码点单，**等叫号**，期间你能干别的。

## 例子

### 同步（你写过的"老土"代码）

```python
# 用户点"生成报告"按钮
result = generate_report()  # 等待 30 秒
return result               # 显示结果
```

**用户体验**：页面**卡住 30 秒** → 显示结果

### 异步（你项目里现在用的）

```python
# 用户点"生成报告"按钮
task_id = start_generate_report()  # 立刻返回任务 ID（< 100ms）
return {"task_id": task_id}       # 前端开始轮询进度
```

**用户体验**：按钮一按立刻有反应 → 看到"生成中 35%" → 完成跳转

## 关键点

- 现代网站**几乎都异步**（用户体验好）
- 你项目里"任务中心"就是异步：**提交任务 → 立刻返回 → 后台慢慢跑 → 进度条更新**
- 异步的实现：
  - **轮询**：前端每秒问"好了没？"
  - **WebSocket**：服务器主动推（聊天用这个）
  - **SSE**：服务器单向推（更轻量）

## 同步 vs 异步：优缺点

| | 同步 | 异步 |
|---|---|---|
| 用户体验 | ❌ 页面卡住 | ✅ 立刻响应 |
| 代码复杂度 | ✅ 简单 | ❌ 复杂（要管状态、要轮询）|
| 调试难度 | ✅ 容易 | ❌ 难（异步链路难追）|
| 服务器压力 | ❌ 长连接占资源 | ✅ 释放资源 |
| 适合场景 | 内部工具、简单查询 | **所有面向用户的产品** |

## 跟你的项目关系

- 你的**报告生成**用异步任务（正确选择，生成慢）
- 你的**支付回调**用同步（必须立即响应支付宝）
- 你的**登录/查询**用同步（够快）

## 高级：协程 / 异步函数

```python
async def fetch_data():           # async 关键字
    data = await api_call()      # await 等异步操作
    return data
```

- Python：`asyncio` + `async/await`
- JavaScript：天生异步（Promise、async/await）
- Go：goroutine（轻量级线程）

## 常见坑

- **回调地狱**：嵌套太多层异步
- **状态丢失**：异步中变量被改
- **死锁**：A 等 B，B 等 A
