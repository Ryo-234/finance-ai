# 进程 vs 线程 - "饭店 vs 服务员"

> ⏱ 阅读时间：1 分钟

## 是什么

| 概念 | 是什么 |
|---|---|
| **进程** | 一个**正在运行的程序**（如你的 FastAPI 跑起来就是一个进程）|
| **线程** | 进程里的**一条执行流**（一个进程可以有多个线程）|

## 类比

- **进程** = 一家**饭店**
- **线程** = 饭店里的**1 个服务员**

一家饭店（进程）有 5 个服务员（线程），同时服务 5 桌客人。

## 关键点

- 进程之间**互不干扰**（A 饭店倒闭不影响 B 饭店）
- 线程共享进程的**内存**（5 个服务员共享厨房资源）

## 为什么关心这个

- 你的项目里"**4 个 worker**" = 4 个进程，每个进程处理一部分请求
- 进程越多，能同时处理的请求越多
- 但**内存消耗也大**（1 个进程 ≈ 100-200MB 内存）

## 进程 vs 线程 对比

| | 进程 | 线程 |
|---|---|---|
| 内存 | 独立 | 共享 |
| 通信 | 难（要用 IPC）| 易（共享变量）|
| 创建开销 | 大 | 小 |
| 一个挂了 | 不影响其他 | 全死（共享内存出错）|
| 适合 | 隔离的服务 | 协作的子任务 |

## 跟你的项目关系

```python
# 你的 run_api.py 启动 Gunicorn：
gunicorn app --workers 4

# 这就是起了 4 个进程
# 每个进程里 FastAPI 处理一部分请求
# 4 个进程 = 4 核 CPU 充分利用
```

## 高级：协程（Coroutine）

- 比线程**更轻量级**的并发
- Python：`asyncio` + `async/await`
- 你的项目里**没用**（因为报告生成是 CPU/IO 密集，线程更合适）

## 怎么管进程

```bash
ps aux              # 看所有进程
ps aux | grep python  # 找 python 进程
kill <PID>          # 温柔杀掉
kill -9 <PID>       # 强制杀掉
top                 # 实时看进程和资源
htop                # top 的升级版（更友好）
```

## 缺了会怎样

- **不知道进程在不在跑** = 不知道服务是否正常
- **不知道为啥挂了** = 查不到内存/CPU 信息
- **不知道怎么杀** = 跑飞了只能重启服务器

## 常见坑

- **僵尸进程**：进程死了但没释放资源（要 `kill -9`）
- **端口占用**：进程没杀干净，新进程起不来（`lsof -i :8001` 查谁占着）
- **进程太多**：内存爆掉（限制 worker 数量）
