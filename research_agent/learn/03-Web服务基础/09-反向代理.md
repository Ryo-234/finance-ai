# 反向代理 - "前台接待"

> ⏱ 阅读时间：1 分钟

## 是什么

站在用户和服务器之间的"前台"，**接收用户请求、分发给后面的服务**。

## 类比

银行大堂前台：
- 用户说："我要开户" → 前台："3 楼 301 窗口"
- 用户说："我要转账" → 前台："2 楼 202 窗口"
- 用户**不知道**（也不需要知道）后面哪个窗口办啥

## 常见软件

- **Nginx**（最流行，占 30%+ 市场份额）
- Apache（老牌）
- HAProxy（高性能）
- Caddy（自动 HTTPS）
- Cloudflare（云服务）

## 你的项目里

```
用户访问 finance-ai.com
   ↓
Nginx（反向代理）
   ├── /api/*  →  转发到后端 :8001
   └── /*      →  转发到前端 :3000
```

**好处**：
- 用户只看到 `finance-ai.com`（不知道有 8001、3000 端口）
- 隐藏真实服务（安全）
- 统一 HTTPS 终止
- 静态文件直接返回（快）

## 反向代理 vs 正向代理

| | 正向代理 | 反向代理 |
|---|---|---|
| 谁用 | 客户端（替你访问）| 服务端（替你接收）|
| 例子 | VPN、翻墙 | Nginx、Cloudflare |
| 类比 | 你让秘书帮你去办事 | 公司前台帮你接客人 |

## 关键点

- **每个 Web 项目几乎都有**
- 大部分用 **Nginx**（轻量、快、稳）
- 配置就一段 `location / { proxy_pass ... }`

## 怎么配（你的项目）

```nginx
server {
    listen 80;
    server_name finance-ai.com;

    # 前端
    location / {
        proxy_pass http://localhost:3000;
    }

    # 后端 API
    location /api/ {
        proxy_pass http://localhost:8001;
    }
}
```

## 缺了会怎样

- 用户要记 `finance-ai.com:3000` 访问前端，记 `finance-ai.com:8001` 调 API
- **每个服务都要单独开端口**，管理混乱
- 没有 HTTPS 终止

## 跟你的项目关系

- **生产部署必装**（PaaS 平台自动帮你配）
- **自建服务器必学**（但配置很简单，10 行）

## 常见坑

- **WebSocket 转发要特殊配置**（普通配置不支持长连接）
- **大文件上传超时**（调 `proxy_read_timeout`）
- **客户端真实 IP 丢失**（要传 `X-Forwarded-For` 头）
