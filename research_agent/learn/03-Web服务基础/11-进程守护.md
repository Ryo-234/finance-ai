# 进程守护 - "服务员倒了立刻换人"

> ⏱ 阅读时间：1 分钟

## 是什么

进程挂了**自动拉起**新进程，保持服务永远在线。

## 类比

饭店员工请假/晕倒 → 老板立刻叫下一个顶上 → 顾客**完全不知道**换过人。

## 为什么需要

服务进程**总有一天会挂**：
- 内存泄漏慢慢 OOM
- 没处理的异常导致崩溃
- 服务器重启
- 代码 bug

**没有进程守护**：挂了 = 永远挂了，直到你手动 SSH 上去重启。
**有进程守护**：挂了 = 几秒内自动重启。

## 常见工具

| 工具 | 场景 |
|---|---|
| **systemd** | Linux 自带，最常用（你的项目会用这个）|
| **supervisor** | 老的工具，现在用得少 |
| **PM2** | Node.js 生态 |
| **Gunicorn workers** | Python 自动重启 worker（部分进程守护）|
| **Docker restart=always** | 容器层面 |
| **云平台自动** | Render/K8s 都自动 |

## 你的项目里

`/etc/systemd/system/research-agent.service` 配置文件（生产部署时）：

```ini
[Unit]
Description=Research Agent API
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/research-agent
ExecStart=/var/www/research-agent/.venv/bin/gunicorn app --workers 4
Restart=always          # ← 关键：挂了自动重启
RestartSec=5            # ← 5 秒后重启

[Install]
WantedBy=multi-user.target
```

## 关键命令

```bash
systemctl start research-agent    # 启动
systemctl stop research-agent     # 停止
systemctl restart research-agent  # 重启
systemctl status research-agent   # 看状态
systemctl enable research-agent   # 开机自启
journalctl -u research-agent -f  # 看实时日志
```

## Gunicorn worker 重启

```bash
# Gunicorn 默认就有 worker 自动重启
# 但**主进程挂了**它管不了
# 所以生产用 systemd 管主进程 + gunicorn 管 worker（双保险）
gunicorn app --workers 4 --max-requests 1000
# 1. 每个 worker 处理 1000 个请求后自动重启（防内存泄漏）
# 2. worker 异常退出 → 主进程立刻拉起新 worker
```

## 关键点

- **生产环境必装**（不用进程守护 = 灾难）
- **云平台（PaaS）默认有**，自建服务器才需要自己配
- 多个层次：systemd 管主进程 + Gunicorn 管 worker + 平台管服务器

## 跟你的项目关系

- 你现在用 `python run_api.py` 直接跑（**没有守护**）
- 生产部署时必须配 systemd 或用 PaaS

## 缺了会怎样

- **服务挂了就永远挂**（你要 ssh 上去手动起）
- 半夜 3 点挂了 → 用户访问报错 → 你**早上 9 点才看到**
- **一晚上没用户**，可能损失几十单

## 常见坑

- **`Restart=always` 没配**（默认不重启）
- **OOM 被系统杀** → system 不知道，不重启（要 `Restart=on-failure` + `OOMPolicy=continue`）
- **配置改了没 reload**：`systemctl daemon-reload` 再 `systemctl restart`
- **日志不知道放哪**：`journalctl -u 服务名` 是默认的
