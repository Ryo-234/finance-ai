# Kubernetes (K8s) - "集装箱调度中心"

> ⏱ 阅读时间：1 分钟

## 是什么

管理**几百几千个 Docker 容器**的系统。**自动化部署、扩缩容、故障恢复**。

## 类比

100 个集装箱（容器）堆在码头（你的服务器集群），K8s 是"调度员"：
- 哪个集装箱放哪艘船（哪台服务器）
- 哪些集装箱要复制几个（流量大了多开几个实例）
- 哪个集装箱坏了换一个（自动重启）
- 哪艘船要卸货（滚动更新）

## 为什么需要

Docker 单机够用，**多机**就麻烦：
- 10 台服务器 + 100 个容器
- 哪台跑哪个？挂了怎么知道？怎么负载均衡？
- 手动管理 = 累死
- **K8s 自动管理**

## 核心概念

| 概念 | 是什么 | 类比 |
|---|---|---|
| **Pod** | 1 个或多个容器的组合（最小单位）| 一个"工位" |
| **Deployment** | 一组相同 Pod 的模板 | "招聘 N 个前端工程师" |
| **Service** | Pod 的固定访问入口（IP 变来变去）| 公司的前台 |
| **Ingress** | 外部访问入口（域名+HTTPS）| 公司的正门 |
| **ConfigMap** | 配置文件 | 工位上的"操作手册" |
| **Secret** | 密钥（base64 编码）| 工位上的"保险箱" |
| **Namespace** | 隔离环境 | 公司里的"部门" |

## 什么时候用

| 规模 | 用什么 |
|---|---|
| 1 个服务 | 不用 K8s，直接 `docker run` |
| 5-10 个服务 | Docker Compose 一键起 |
| **50+ 服务** | **上 K8s** |
| 500+ 服务 | K8s + 周边生态（Istio/Argo/...）|

## 关键点

- **个人项目用不到**（太重）
- **JD 常写"熟悉 K8s 加分"**（不是必备）
- **学习成本高**（1-2 周入门）
- **运维岗必会**，**开发岗加分**

## 跟你的项目关系

- **现在用不到**（你项目就 2 个服务）
- **以后真要做大**：先学 Docker Compose，再考虑 K8s

## 怎么学（如果想）

- **官方教程**：[kubernetes.io/zh-cn/docs/tutorials](https://kubernetes.io/zh-cn/docs/tutorials/)
- **本地试用**：[minikube](https://minikube.sigs.k8s.io/)（单机 K8s）
- **云上试用**：阿里云 ACK / 腾讯云 TKE（托管 K8s）

## 缺了会怎样

- **不会缺**（个人项目用不到）
- **但面试时**：懂 K8s = 基础 DevOps 水平（加分）

## 高级：K8s 生态

- **Helm**：K8s 的包管理器（一键装复杂应用）
- **Istio**：服务网格（流量管理、安全、监控）
- **Argo CD**：GitOps 工具（Git 改了 K8s 自动同步）
- **Prometheus + Grafana**：K8s 监控
- **cert-manager**：自动 HTTPS 证书

## 常见坑

- **学习曲线陡**：从 0 到会用至少 1-2 周
- **资源消耗大**：K8s 控制平面本身要 2-3 台机器
- **新手用错配置**：生产事故常因 K8s 配错
