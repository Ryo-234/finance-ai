# 消息队列 - "留言板"

> ⏱ 阅读时间：1 分钟

## 是什么

A 程序发消息到**队列**，B 程序**异步**取消息处理。**解耦 + 削峰**。

## 类比

饭店前台接电话**留言**："您要订 10 人位，明天 7 点"
- 前台记到小本本上（**消息队列**）
- 经理晚上 8 点下班后看本子（**消费者**）
- 经理挨个回拨处理

前台不用**立刻**找经理处理，**先记下来**就行。

## 为什么需要

### 场景 1：解耦

- 没队列：A 调 B → B 挂了 → A 也跟着挂（**紧耦合**）
- 有队列：A 发到队列 → A 立刻返回（**不管 B**） → B 慢慢处理

### 场景 2：削峰

- 双 11 大促：1 秒 10 万订单
- 没队列：服务器**直接挂**（处理不过来）
- 有队列：订单都进队列（队列扛得住 100 万），**慢慢处理**（每分钟处理 1000 个）

## 常见消息队列

| 名字 | 特点 | 适合 |
|---|---|---|
| **RabbitMQ** | 老牌、功能全 | 复杂业务（订单、支付）|
| **Kafka** | 高吞吐、分布式 | 日志、监控、流式 |
| **Redis Streams** | 轻量（你已有 Redis）| 简单任务 |
| **RocketMQ** | 阿里出品 | 国内电商大流量 |
| **AWS SQS** | 云服务 | 用 AWS 的项目 |

## 你的项目里

**目前不用**，但**未来会用**：

```python
# 比如：用户提交报告生成任务
# 现在你用：直接调后端函数（同步）
# 未来用：扔到队列（异步 + 削峰）

# 用户立刻收到"已提交"响应
# Worker 慢慢从队列取任务处理
```

## 跟你的项目关系

- 你的"任务中心"已经是**轻量级任务队列**（数据库 polling）
- **生产场景**（100 并发）：建议换 RabbitMQ / Celery + Redis
- **MVP 阶段**（10 用户以内）：数据库 polling 够用

## 关键点

- **3 个角色**：
  - **生产者**：发消息的（A）
  - **队列**：存消息的（小本本）
  - **消费者**：取消息处理的（B）
- **不丢消息**：持久化到磁盘
- **顺序保证**：某些队列（Kafka）保证按顺序处理

## 缺了会怎样

- **小项目**不会缺
- **大流量项目**没队列 = 活动一来就挂

## 怎么用

```python
# 以 Celery + Redis 为例（最常见的 Python 方案）
from celery import Celery
app = Celery('tasks', broker='redis://localhost:6379')

@app.task
def generate_report(user_id, topic):
    # 干活
    pass

# 调用：异步
generate_report.delay(user_id, topic)  # 立刻返回，后台慢慢跑
```

## 常见坑

- **消息丢失**：没配持久化
- **重复消费**：网络抖动导致重发（**幂等设计**很重要）
- **队列堆积**：消费太慢（**加 worker** 或 **优化消费速度**）
- **死信队列**：处理失败的消息一直阻塞（要单独存起来人工处理）
