# 缓存 (Redis) - "短期记忆"

> ⏱ 阅读时间：1 分钟

## 是什么

把常用数据放**内存**里（超快），不用每次查**数据库**（慢）。

## 类比

你不用每次都去图书馆查"Python 怎么写"，**记住就行**。

| | 内存 (Redis) | 数据库 (PostgreSQL) |
|---|---|---|
| 速度 | 0.1 ms | 10 ms（**100 倍**）|
| 容量 | 小（GB 级）| 大（TB 级）|
| 成本 | 高 | 低 |
| 用途 | **临时常用数据** | 持久数据 |

## 你的项目里

**你已经有 Redis 缓存**（在 `db/repositories/cache_repo.py`）：

```python
# 报告缓存：同 query 第二次生成秒级返回
cache_key = md5(user_id + topic + report_type)
if cache.exists(cache_key):
    return cache.get(cache_key)  # 0.1ms 拿到
else:
    report = generate()         # 30 秒
    cache.set(cache_key, report, ttl=24*3600)
```

## 常见缓存策略

### Cache-Aside（最常用，你项目里就是）

```
读：先查缓存 → 命中返回 → 未命中查库 + 写缓存
写：直接写库 + 删除缓存（不是更新缓存）
```

### Write-Through

```
写：先写缓存 → 缓存自动同步写库
（强一致，但写慢）
```

### Write-Behind

```
写：只写缓存 → 异步批量写库
（快，但可能丢数据）
```

## 常见坑

### 1. 缓存穿透

**问题**：每次请求都查不到缓存（如攻击者故意查不存在的 ID），全打数据库
**解决**：缓存空值（`cache.set("user:99999", None, ttl=60)`）

### 2. 缓存击穿

**问题**：热点 key 过期瞬间，大量请求同时打数据库
**解决**：永不过期 + 异步刷新，或加锁

### 3. 缓存雪崩

**问题**：大量 key 同时过期，请求全打数据库
**解决**：过期时间**加随机值**（`ttl = 3600 + random(0, 600)`）

## 关键点

- **不是所有数据都该缓存**（频繁读 + 改动少 + 不要求强一致）
- **TTL（过期时间）必设**（不然内存爆）
- **更新数据要更新缓存**（否则用户看到旧数据）

## 跟你的项目关系

- **已经在用**（报告缓存 24h TTL）
- 后续优化：加**用户级缓存**（当前用户用量、订单列表等）

## 缺了会怎样

- **每次请求都查数据库** → 数据库压力大 → 慢
- **没缓存的网站 = 每次都"想半天"**

## 怎么用（Python）

```python
import redis
r = redis.Redis(host='localhost', port=6379)

# 写
r.set('key', 'value', ex=3600)  # ex=秒

# 读
val = r.get('key')

# 删
r.delete('key')

# 高级：Hash / List / Set
r.hset('user:1', 'name', 'Ryo')
r.hget('user:1', 'name')
```
