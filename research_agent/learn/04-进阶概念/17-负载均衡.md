# 负载均衡 - "排队叫号机"

> ⏱ 阅读时间：1 分钟

## 是什么

把请求**分给多台服务器**处理。**避免一台机器过载**。

## 类比

银行 5 个窗口，**客户分流**到不同窗口办业务：
- 客户 1 来 → 叫号机："1 窗口"
- 客户 2 来 → 叫号机："3 窗口"
- 客户 3 来 → 叫号机："2 窗口"
- **没人排队**（5 个窗口同时办）

## 解决了什么问题

**没有负载均衡**：
- 1 台服务器扛 1000 用户 → CPU/内存爆 → 全站慢/挂

**有负载均衡**：
- 3 台服务器各扛 333 用户 → 都轻松 → 用户快

## 关键点

- **多台服务器**才能负载均衡（1 台没意义）
- **用户不知道**有 LB（透明）
- **挂了自动剔除**：某台服务器宕机，LB 不再发请求给它

## 常见算法

| 算法 | 描述 | 适合 |
|---|---|---|
| **轮询（Round Robin）** | 1→2→3→1→2→3 | 服务器性能相同 |
| **最少连接** | 找当前连接最少的 | 长连接（如 WebSocket）|
| **IP 哈希** | 同一用户总到同一台 | 需要会话保持 |
| **加权轮询** | 性能好的多分配 | 服务器性能不均 |
| **随机** | 随机选一台 | 服务器性能相同 |

## 常见工具

| 工具 | 特点 |
|---|---|
| **Nginx**（upstream 模块）| 最常用，简单 |
| **HAProxy** | 性能最强 |
| **LVS**（Linux Virtual Server）| 内核级，性能怪兽 |
| **云 LB**（AWS ELB、阿里云 SLB）| 云厂商托管，不用自己搭 |
| **Cloudflare** | 边缘 LB，全球节点 |

## 跟你的项目关系

- **现在不用**（1 台服务器够用）
- **2-3 台服务器**时配 Nginx upstream
- **云平台**（Render）自动给你 LB

## 配置示例（Nginx）

```nginx
upstream backend {
    server 10.0.0.1:8001;
    server 10.0.0.2:8001;
    server 10.0.0.3:8001;
}

server {
    listen 80;
    location /api/ {
        proxy_pass http://backend;
    }
}
```

## 缺了会怎样

- **小项目**不会缺
- **大流量**没 LB = 1 台扛不住 = 全站挂

## 高级：四层 vs 七层 LB

| | 四层（L4）| 七层（L7）|
|---|---|---|
| 看哪层 | TCP/IP | HTTP |
| 速度 | ⚡ 极快 | 慢一点（要解析 HTTP）|
| 功能 | 只按 IP/端口分 | 按 URL/Header/Cookie 分 |
| 工具 | LVS | Nginx、HAProxy |
| 适合 | 性能要求极高 | **绝大多数场景**（含 SSL 终止）|

## 常见坑

- **会话丢失**：用户登录状态丢失（用 Redis 共享 session）
- **上传大文件慢**：流量只到 1 台（用专门的"上传服务器"）
- **数据库连接数爆**：100 台服务器都连 1 个 DB（DB 先挂）→ DB 用连接池
- **健康检查配错**：挂了的服务还在 LB 池里
