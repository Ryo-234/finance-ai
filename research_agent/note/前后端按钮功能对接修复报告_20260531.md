## 问题 1：create_thread 参数格式不匹配

### 现象
前端点击"新建会话"按钮后，`createThread()` 发送 JSON Body：
```json
{ "channel": "api", "chat_id": "anonymous" }
```
但后端 `POST /api/threads/` 接收的是 **query params**，导致 `channel` 和 `chat_id` 始终为默认值。

### 根因
`api/routers/threads.py:125` 的 `create_thread` 函数参数定义为普通 Python 参数：
```python
async def create_thread(channel: str = "api", chat_id: str = "anonymous"):
```
FastAPI 默认将非 Body/Form 的参数解析为 query params，不会从 JSON Body 中提取。

### 修复
**文件**：`api/routers/threads.py`

新增 Pydantic 请求体模型，将参数改为接收 JSON Body：
```python
class CreateThreadRequest(BaseModel):
    channel: str = "api"
    chat_id: str = "anonymous"
    user_id: Optional[str] = None

@router.post("/", response_model=ThreadResponse)
async def create_thread(body: CreateThreadRequest):
    thread_id = create_thread_meta(body.channel, body.chat_id, body.user_id)
```

## 问题 2：get_messages 空桩实现

### 现象
`GET /api/chat/{thread_id}/messages` 始终返回 `{"messages": [], "count": 0}`，即使用户在该线程中有过对话。

### 根因
`api/routers/chat.py:300` 的 `get_messages` 函数直接返回空列表，注释写道"简化实现：直接返回空列表"。

### 修复
**文件**：`api/routers/chat.py`

实现从 Checkpointer (InMemorySaver) 读取真实检查点数据：
```python
checkpoint_tuple = checkpointer.get_tuple(config)
if checkpoint_tuple is None:
    return {"thread_id": thread_id, "messages": [], "count": 0}

checkpoint = checkpoint_tuple.checkpoint
channel_values = checkpoint.get("channel_values", {})
messages = channel_values.get("messages", [])
formatted = format_messages_for_display(messages)
```

## 问题 3：前端 selectThread 不加载消息历史

### 现象
用户在侧边栏点击某个历史线程后，聊天区域显示空白，看不到之前的对话内容。

### 根因
`hooks/useChat.ts:57` 的 `selectThread` 函数直接设置 `messages: []`，从未调用后端 API 加载消息历史。

### 修复
**文件**：`frontend/src/core/api.ts`
- 新增 `getMessages(threadId, limit)` 方法

**文件**：`frontend/src/hooks/useChat.ts`
- 新增 `loadMessages` 异步函数，调用 `api.getMessages()` 加载消息
- 新增 `useEffect` 监听 `currentThread?.threadId` 变化，自动触发 `loadMessages`
- 选中线程后自动加载历史消息并填充到 UI
