## 二、核心问题：流式输出截断

### 2.1 现象

前端流式输出内容被截断，只显示前半部分。

### 2.2 排查过程（讲师模式）

第一步，怀疑后端。用 curl 直接测试流式端点，得到 9-30 个 chunk，answer 完整（551 字），title 正常。**后端没问题。**

第二步，怀疑前端 SSE 解析。重写为标准双换行分割、加 JSON 异常保护、适配 \r\n。截断依然存在。

第三步，加诊断日志。在 `onChunk` 中累加字数，在 `onDone` 中打印。得到关键数据：

```
SSE 完成: 25 chunk, 1376 字, answer_len=1376
```

**字数完全匹配！** 说明所有数据都成功传到了前端 JavaScript。问题不在传输层。

第四步，定位到 **React 渲染层**。`onChunk` 每次收到文本就调一次 `setCurrentThread`，25 个 chunk 就是 25 次状态更新。React 18 的函数式更新（`prev => ...`）理论上不会丢，但在快速连续调用的场景下，某些中间更新可能被覆盖。

### 2.3 解决方案

用 `useRef` 作为流式文本的"蓄水池"：

```typescript
// 之前：每次 chunk 都 setState
onChunk = (text) => {
  setCurrentThread(prev => {
    // 取出最后一条消息，追加 text，放回去
    // 问题：25 次快速 setState，React 可能丢中间状态
  })
}

// 之后：ref 累积，setState 始终拿到完整文本
const streamBufferRef = useRef('')

onChunk = (text) => {
  streamBufferRef.current += text  // ref 同步更新，从不丢失
  setCurrentThread(prev => {
    // 直接用 ref.current 作为完整文本，不依赖 prev
    msgs[last].content = streamBufferRef.current
  })
}
```

这个方案的要点：**ref 是同步的，永远拿到最新的累积值；state 是异步的，存在时间窗口问题。**

## 三、会话标题自动生成

### 3.1 TitleMiddleware 设计

参考 DeerFlow 的 `TitleMiddleware`，继承 `BaseMiddleware`：

- 挂载 `after_agent` 钩子（覆盖所有意图路径）
- 检查条件：title 为空、有 1 条用户消息、有 AI 回复
- 调用 LLM 生成 ≤15 字标题
- 失败时回退到用户消息前 20 字符 + "..."

### 3.2 标题持久化

标题生成后写入 `_threads_meta` 字典。下次同一线程发消息时，`run_research` 从 `_threads_meta` 读回已有标题注入 state，中间件检查到非空直接跳过。

### 3.3 踩坑记录

1. `after_agent` 返回值被 `run_research` 忽略 → 加 `result = {**result, **agent_result.updates}`
2. chat.py 引用 `_threads_meta` 未导入 → 加 `from api.routers.threads import _threads_meta`
3. 问候路径无 AIMessage → 兼容从 `greeting_response` 提取 AI 上下文
