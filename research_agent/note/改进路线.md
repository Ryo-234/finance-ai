# Research Agent 实习项目改进路线

## 项目现状

Research Agent 基于 FastAPI + LangGraph + Next.js 15，目标是构建智能研究助手。经全面审计，项目当前评分如下：

| 维度 | 评分 | 关键差距 |
|------|------|----------|
| 功能完整度 | 6/10 | RAG/Knowledge Agent 是空桩、MCP 管道是死代码 |
| 前端 | 5/10 | 仅 2 个页面、零可复用组件 |
| 中间件 | 7/10 | TokenBudget 空桩、Summarization 不调 LLM |
| 记忆系统 | 8/10 | API 路由方法名与存储类不匹配 |
| 测试 | 3/10 | 无 API 测试、无前端测试、无 CI/CD |
| 安全 | 2/10 | 零认证、零授权、CORS 全开、无速率限制 |
| 配置管理 | 5/10 | config.yaml 值被硬编码覆盖 |
| 部署 | 0/10 | 无 Dockerfile、无 CI/CD |

## 第一周：P0 严重问题修复

### Day 1：两个代码级 Bug 修复

**P0-1：修复 memory API 方法名不匹配**
- 问题：`api/routers/memory.py` 调用 `storage.load_memory()` / `storage.save_memory()`，但 `FileMemoryStorage` 暴露的方法是 `load()` / `save()`
- 影响：调用记忆 CRUD API 会抛出 AttributeError
- 修复：在 `memory/storage.py` 中添加 `load_memory()` / `save_memory()` 别名方法，同时修复路由中的调用
- 涉及文件：`memory/storage.py`、`api/routers/memory.py`

**P0-2：修复 MiddlewareResult 参数名错误**
- 问题：`middleware/manager.py` 中 4 处 `MiddlewareResult(updated=...)` 参数名错误，`MiddlewareResult` 的字段名是 `updates`
- 影响：中间件的更新结果无法正确传递，导致记忆保存等异步操作失效
- 修复：将 4 处 `updated=` 改为 `updates=`
- 涉及文件：`middleware/manager.py`

### Day 2-3：激活 RAG Agent

**P0-3：实现 RAG Agent 接入向量检索**
- 问题：`agents/rag_agent.py` 的 `ainvoke` 永远返回空列表 `rag_results: []`
- 修复：接入 ChromaDB 向量数据库，实现文档嵌入、存储和检索
- 在 LangGraph 图中新增 `rag` 节点，放在 search 和 knowledge 之间
- 涉及文件：`agents/rag_agent.py`、`graph/research_graph.py`、`graph/state.py`

### Day 4：激活 Knowledge Agent + MCP 管道

**P0-4：激活知识库 Agent 和 MCP 工具链路**
- 问题：`agents/knowledge_agent.py` 是空桩，MCP 工具已加载但从未被 Agent 调用
- 修复：从 ToolRegistry 获取 MCP 工具，实现动态工具调用
- 涉及文件：`agents/knowledge_agent.py`、`mcp_integration/tools.py`

### Day 5：回归测试与验证
- 端到端验证聊天全链路：Planner → Search → RAG → Knowledge → Synthesizer
- 确保所有 P0 修复不引入新问题

## 第二周：P1 核心增强

### Day 1-2：API 认证

**P1-1：实现 API Key 认证中间件**
- 新建 `middleware/auth.py`，检查 `Authorization: Bearer <token>` 头
- 从 `.env` 读取有效 token 列表，支持多 token
- 在 `api/app.py` 中注册认证中间件
- 涉及文件：`middleware/auth.py`（新建）、`api/app.py`

### Day 2-3：速率限制

**P1-2：实现请求速率限制**
- 新建 `middleware/rate_limit.py`，基于 IP 或 token 限流
- 默认每个用户每分钟 30 次请求，可通过 `config.yaml` 配置
- 使用 `asyncio-throttle`（已在 requirements.txt 中）
- 涉及文件：`middleware/rate_limit.py`（新建）、`api/app.py`

### Day 3-4：真正的流式输出

**P1-3：从"假流式"改为真正的逐 token 流式**
- 当前问题：Agent 完全执行完毕后，API 按 50 字符分块发送（假流式）
- 修复：重写 `run_research` 为异步生成器，每个节点完成后立即 yield 结果
- 前端 SSE 适配新的事件格式
- 涉及文件：`graph/research_graph.py`、`api/routers/chat.py`、`frontend/src/core/api.ts`

### Day 5：LLM 摘要中间件

**P1-4：实现真正的 LLM 摘要**
- 实现 `TokenBudgetMiddleware`（当前是空桩）
- 改进 `SummarizationMiddleware`，调用 LLM 生成对话摘要（而非纯文本截断）
- 涉及文件：`middleware/summarization.py`、`middleware/token_tracking.py`
