## 问题描述

用户报告：research_agent 在发送**业务模式**消息时出现问题，但**闲聊模式**正常。

**测试命令**：

## 发现的问题

### 问题 1: 记忆模块 API 不匹配

**严重程度**: 高

**错误日志**：
```
middleware.memory - ERROR - 加载记忆上下文失败: 'FileMemoryStorage' object has no attribute 'load_memory'
Traceback:
  File "middleware/memory.py", line 302, in _load_memory_context
    memory_data = storage.load_memory(user_id=user_id, agent_name="research")
AttributeError: 'FileMemoryStorage' object has no attribute 'load_memory'
```

**Root Cause**：
- `middleware/memory.py` 调用 `storage.load_memory(user_id=..., agent_name=...)`
- 但 `FileMemoryStorage` 只有 `load()` 方法，没有 `load_memory()` 方法
- 参数顺序也不匹配

**API 对比**：
| 组件 | research_agent 调用 | FileMemoryStorage 实际方法 |
|------|-------------------|------------------------------|
| 方法名 | `load_memory()` | `load()` |
| 参数 | `user_id, agent_name` | `agent_name, *, user_id` |

**影响**：业务模式会触发中间件的 `before_model`，其中调用 `_load_memory_context` 失败。

---

### 问题 2: 前端无限轮询

**严重程度**: 中

**观察**：日志显示大量重复的 `GET /api/threads/{thread_id}` 请求

```
GET /api/threads/f7e02125 HTTP/1.1  (重复数百次)
```

**Root Cause**：
- `useChat.ts` 中 `startPolling` 设置 5 秒轮询
- 消息发送成功后未停止轮询
- 导致持续向服务器发送请求

---

## 为什么闲聊模式正常

根据 `planner.py` 的意图识别逻辑：

- `greeting` intent → 直接返回问候，**不走完整流程**
- `task` intent → 经过 planner → search → knowledge → synthesizer **完整流程**

闲聊被识别为 `greeting`，走短路逻辑直接结束，所以不受记忆模块 bug 影响。

---

## 修复方案

### 修复 1: 修正 memory.py 的 API 调用

**文件**: `middleware/memory.py`

**位置**: `_load_memory_context` 方法（约第 296-302 行）

```python
# 修改前（错误）
from memory.storage import FileMemoryStorage
storage = FileMemoryStorage()
memory_data = storage.load_memory(user_id=user_id, agent_name="research")

# 修改后（正确）
from memory.storage import get_memory_storage
storage = get_memory_storage()
memory_data = storage.load(agent_name="research", user_id=user_id)
```

### 修复 2: 优化前端轮询逻辑

**文件**: `frontend/src/hooks/useChat.ts`

在 `sendMessage` 的 `onDone` 回调中，消息完成后停止轮询。
